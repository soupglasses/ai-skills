# The book

How an agent's work goes wrong while looking helpful, thorough, or compliant. Rules are
derived from it, and reviews cite it by entry number.

| Chapter | Subject |
| --- | --- |
| [01-contexts.md](01-contexts.md) | Writing for the conversation when the reader is elsewhere |
| [02-scope.md](02-scope.md) | Work that grows past the request |
| [03-literal-reading.md](03-literal-reading.md) | Following the wording and missing the purpose |
| [04-evidence.md](04-evidence.md) | Tests and reports that cannot show a failure |
| [05-rules.md](05-rules.md) | Wording an instruction for an agent |
| [06-law.md](06-law.md) | What legal theory and drafting practice say about rules |
| [07-generated-files.md](07-generated-files.md) | Editing a generated or vendored file instead of its source |
| [99-sources.md](99-sources.md) | The sources cited |

An entry states the failure, a **Check** to answer from the artifact, a **Repair**, and a
**Basis**: a source key with what that source found, or `Observed` for the maintainer's own
observation.

- Report an entry only where the artifact shows it. A clean result is valid.
- An entry describes a decision that went wrong. It does not ban the technique.
- Cite a source only for a statement it makes, after reading it. Quote it where cited.
- Entry numbers are fixed once assigned. Keep private incidents out.
